01 / 六个概念

先懂这六件事，后面就不容易慌

每个概念只保留「它是什么、为什么、我该怎么用」。看不懂原理也没关系，先把操作记住。

01 · NETWORK

测试网 Sepolia

主网的 ETH 是真钱；Sepolia 是测试网，规则一样，但 ETH 是假的、免费领的。

链 ID 11155111 · 浏览器 sepolia.etherscan.io

02 · ACCOUNT

账户、私钥、地址

私钥是一个 256 位随机数，谁拿到它谁就能控制账户；地址由私钥推导出来，可以公开；助记词是生成多个私钥的种子。

交易用私钥签名，节点用签名恢复出地址。

03 · RPC

RPC 节点

钱包和 Hardhat 自己不存区块链数据，它们通过 RPC 节点读写链。

读 eth_call 不花 gas；写要签名交易、花 gas。

04 · GAS

Gas 和 Nonce

Gas 是每个操作的计算成本，用 Sepolia ETH 支付；Nonce 是账户的交易计数器，从 0 开始，每发一笔 +1。

一笔卡住，后面的都会排队。按 nonce 顺序执行可以防重放。

05 · ABI

合约、ABI、验证

合约部署后有地址，里面存代码和状态；ABI 描述函数和参数；验证是把源码交给 Etherscan 重编译并对比字节码。

链上只存字节码，不验证就没有 Read / Write Contract。

06 · PROXY

代理与 UUPS 升级

用户永远只和 Proxy 交互，数据存在 Proxy；实现合约只提供逻辑代码；升级只换 Proxy 里记录的实现地址。

永远对 Proxy 地址读写，不要直接写实现合约。

RPC 到底在做什么

验证为什么能让 Etherscan 出现按钮

代理一句话

Proxy 存数据，Implementation 存代码，delegatecall 让代码在 Proxy 的存储上执行。升级只改 Proxy 里那一格实现地址。更完整的图解见同目录的 proxy-explained.html。

单位换算速查

概念单位例子
ETHwei，1 ETH = 10^18 wei0.01 ETH = 10000000000000000
USDC6 位小数，1 USDC = 10^610 USDC = 10000000
手续费bps，1% = 100 bps5% = 500；金额 × 500 / 10000
时间秒5 分钟 = 300

Solidity 没有小数，所有金额都用整数的最小单位表示。USDC 的 decimals() 是 6，所以 1 USDC 在链上是 1,000,000。

03 / 作业 2

BeggingContract 上链

作业 2 的目标很短：把讨饭合约部署到 Sepolia，验证，然后在 Etherscan 上完成捐赠、查询和提现，截四张图。

2.1

部署到 Sepolia

npx hardhat ignition deploy ignition/modules/BeggingContract.ts --network sepolia --deployment-id begging-sepolia
预期输出

先看到编译，再看到 Batch #1 ...，最后打印：

BeggingContractModule#BeggingContract - 0x....

把这个地址填进附录 B 的地址表，这就是作业要交的合约地址。

如果中途失败（比如水不够），重新执行同一条命令即可。Ignition 会从上次进度继续，不会重复部署已成功的合约。

原理

部署合约是一笔「没有收款地址」的交易，数据里是编译后的字节码。EVM 执行它，把运行时字节码存到新地址。新地址由「部署者地址 + nonce」决定。

2.2

验证合约

npx hardhat ignition verify begging-sepolia --network sepolia

预期看到每个合约的验证结果，最后类似 Successfully verified。

如果失败，先检查 ETHERSCAN_API_KEY 是否设置；刚部署完 Etherscan 可能要几十秒才索引到，等 1 分钟重试。也可以单独验证：

npx hardhat verify --network sepolia <BeggingContract地址> 7

最后的 7 是构造参数 durationDays = 7。

原理

Etherscan 用你提交的源码重新编译，把得到的字节码和链上字节码对比。完全一致才通过。验证不是必须的，但不验证就没有 Read / Write Contract 页面。

2.3

在 Etherscan 上测试

打开 https://sepolia.etherscan.io/address/<BeggingContract地址>，确认有 Read Contract 和 Write Contract 两个标签。

① 捐赠（截图 1）

  1. 点 Write Contract
  2. 点 Connect to Web3 → 选 MetaMask → 连接 A 账户
  3. 找到函数 Donate（注意大写 D）
  4. 展开：Value 填 0.01（单位选 ETH），其他不用填
  5. 点 Write → MetaMask 确认，等交易成功

预期 Logs 里有 Donation 事件，参数是 donor、amount、total、timestamp。截图：交易详情页 + 事件。

原理

Donate 是 payable 函数，MetaMask 里的 Value 会变成合约的 msg.value。合约检查 msg.value >= 0.001 ETH，把金额记到 donations[msg.sender]。

② 查询（截图 2）

函数输入预期
getDonationA 的地址10000000000000000（0.01 ETH 的 wei）
totalDonated无同上
donorCount无1
top3无第一个是 A，另外两个零地址

截图：getDonation 的结果。

原理

mapping(address => uint256) public donations 会自动生成一个 donations(address) getter；getDonation 是手写的另一个入口，效果一样。 public 变量在 ABI 里就是一个只读函数。

③ 提现（截图 3）

  1. Write Contract → 仍然连接 A（只有 owner 能提现）
  2. 找到 withdraw
  3. 点 Write → 确认
  4. 交易成功后：Read → balance() → 0；Read → getDonation(A) → 仍然是 0.01 ETH（历史记录保留）

截图：withdraw 交易详情 + balance() 为 0。

如果用 B 账户点 withdraw，会看到 NotOwner() 报错，这是正常的权限保护，也可以截图作为「权限测试」。

原理

withdraw 上有 onlyOwner 修饰器，执行前检查 msg.sender == owner。合约用 call 把全部余额转给 owner，并用 nonReentrant 防止重入。donations 是历史累计，提现不会清零；address(this).balance 才是合约里真实剩余。

04 / 作业 3

NFT 拍卖市场上链

作业 3 的主线：部署四个合约 → 铸造 NFT → 卖家授权并创建拍卖 → 买家出价 → 被超过后退款 → 结算 → 升级 V2。先看清合约之间的关系。

A · DEPLOYER

部署 + 铸造 + 升级

部署四个合约、调用 mint 把 NFT 发给 B、最后执行 V2 升级。

B · SELLER

授权 + 创建拍卖

approve(Proxy, tokenId)，再调 createAuction。NFT 会被托管进 Proxy。

C · BIDDER

出价 + 退款 + 拿 NFT

ETH 拍卖直接带 Value；USDC 拍卖先 approve 再 bid。被超过后自己 WithdrawRefund。

3.1

部署四个合约

npx hardhat ignition deploy ignition/modules/NFTAuctionMarketSepolia.ts --network sepolia --deployment-id nft-auction-sepolia --parameters ignition/parameters/sepolia.json
预期输出

四个地址：MyNFT、NFTAuctionMarket（实现）、NFTAuctionMarketProxy（代理）、Market（和 Proxy 同地址）。

名称用途要不要直接写
MyNFTERC721，铸造和授权铸造、approve 时用
NFTAuctionMarket实现合约，只有逻辑不要直接写
NFTAuctionMarketProxy代理，存所有拍卖数据所有交互都用它

全部填进附录 B 的地址表，并标注「交互用 Proxy」。部署记录在 ignition/deployments/nft-auction-sepolia/deployed_addresses.json。

原理

部署模块会自动调用 initialize 设置 owner、手续费、ETH 价格源，并调用 setTokenFeed 配置 USDC 价格源。Proxy 存数据，实现合约只提供代码。

3.2

验证

npx hardhat ignition verify nft-auction-sepolia --network sepolia

预期 MyNFT、实现、Proxy 都被验证。验证完打开 Proxy 地址 的 Etherscan 页面，应该出现 Read as Proxy / Write as Proxy。

如果没出现，点页面上的 More Options → Is this a proxy?，按提示确认。

原理

Etherscan 读 ERC1967 规定的存储槽（0x3608...bbc），发现里面是一个已验证的实现地址，就会把实现的 ABI 挂到代理页面上。

3.3

铸造 NFT（用 A 账户）

  1. 打开 MyNFT 地址 的 Etherscan → Write Contract
  2. Connect to Web3 → 连接 A（MyNFT 的 owner）
  3. 找到 mint
  4. 填写 to：B 的地址（卖家）；uri：ipfs://demo/1（任意字符串）
  5. Write → MetaMask 确认
预期

Logs 里有 Minted 事件，tokenId = 1；ownerOf(1) → B 的地址；tokenURI(1) → ipfs://demo/1；totalMinted() → 1。

截图：mint 交易 + Minted 事件。

原理

mint 有 onlyOwner，只有 A 能调用。_safeMint 会检查接收方合约是否实现 onERC721Received，防止 NFT 被永久锁死。_nextTokenId 从 1 开始，所以第一个 NFT 的 tokenId 是 1。

3.4

创建拍卖（用 B 账户）

第一步：授权市场

  1. 打开 MyNFT 地址 → Write Contract
  2. Connect to Web3 → 切到 B
  3. 找到 approve
  4. 填写 to：Proxy 地址；tokenId：1
  5. Write → 确认
原理

ERC721 默认不允许别人转走你的 NFT。approve(proxy, 1) 表示「允许 Proxy 转走 tokenId=1 这一个 NFT」。市场在 createAuction 里会调用 transferFrom(B, 市场, 1)，把 NFT 托管进市场。也可以调用 setApprovalForAll(proxy, true)，一次授权所有 NFT。

第二步：创建拍卖

打开 Proxy 地址 → Write as Proxy，连接 B，找到 createAuction。

nftMyNFT 地址MyNFT 地址
tokenId11

startPrice10000000000000000（0.01 ETH）10000000（10 USDC）
duration300（5 分钟）300

Write → 确认。

预期

Logs 里有 AuctionCreated，auctionId = 0；auctionCount() → 1；getAuction(0) 的 seller 是 B、价格正确、active = true；isActive(0) → true；ownerOf(1) → Proxy 地址（NFT 已托管，正常）。

注意

createAuction 不是 payable，Value 留 0。payToken = 0x0 表示原生 ETH；填 USDC 地址表示 ERC20。duration 必须在 60 秒到 30 天之间。

为什么 NFT 会到市场手里

如果 NFT 一直留在卖家手里，卖家可以在拍卖期间转走 NFT，拍卖结束时无法交割，买家的钱就卡死了。所以 createAuction 会把 NFT 托管（escrow） 到市场合约里。卖家既不能转走，也不能撤销授权。拍卖结束后，市场再把 NFT 转给赢家。

3.5

ETH 出价（用 C 账户）

  1. 打开 Proxy 地址 → Write as Proxy
  2. 连接 C（不能是 B，卖家出价会 SellerCannotBid）
  3. 找到 bid
  4. 填写 auctionId：0；amount：10000000000000000（0.01 ETH，wei）；Value：0.01（Etherscan 的 Value 单位是 ETH）
  5. Write → 确认
预期

BidPlaced 事件里 amount = 0.01 ETH，usdValue = 20000000000000000000（按 $2000 算的 20 USD，18 位小数）；getAuction(0) 的 highestBid / highestBidder 更新；合约 ETH 余额 = 0.01 ETH。

第二次出价必须至少高 5%：amount = 10500000000000000（0.0105 ETH），Value = 0.0105。

原理

amount 是 uint256，单位 wei；Value 是交易附带的 ETH，单位 ETH。两者必须相等，否则 revert EthAmountMismatch。第一次出价 minBid = startPrice；之后 minBid = highestBid + highestBid × 5%，防止 +1 wei 刷价。合约把出价转成美元只是为了事件里给用户看，拍卖内部比较仍用原始代币金额。

3.6

USDC 出价（用 C 账户）

第一步：授权 USDC

  1. 打开 USDC 地址（0x1c7D...7238）→ Write Contract
  2. 连接 C
  3. 找到 approve
  4. 填写 spender：Proxy 地址；amount：10500000（10.5 USDC，6 位小数）
  5. Write → 确认

第二步：出价

  1. 打开 Proxy 地址 → Write as Proxy，连接 C
  2. bid：auctionId = 0；amount = 10500000（10.5 USDC）；Value 留 0
  3. Write → 确认
预期

BidPlaced 事件里 amount = 10500000，usdValue = 10500000000000000000（10.5 USD，18 位小数）；合约 USDC 余额增加 10.5。

原理

ERC20 不是原生币，不能通过 msg.value 发送。市场用 safeTransferFrom(C, 市场, amount) 把 USDC 拉进来。approve 是 ERC20 的授权机制：C 允许市场最多花自己多少 USDC。没有授权，safeTransferFrom 会 revert ERC20InsufficientAllowance。如果是 ERC20 拍卖，bid 的 Value 必须为 0，否则 EthAmountMismatch。

3.7

被超过后退款

  1. 让另一个账户 D 出更高价（比如 0.011 ETH 或 11 USDC）
  2. C 被超过后，Read pendingReturns(0, C的地址) → 显示 C 之前出的金额
  3. C 打开 Write as Proxy → WithdrawRefund，auctionId = 0
  4. 确认后，C 的 ETH/USDC 退回
预期

退款成功；再次调用会 revert NothingToRefund。

截图：pendingReturns + 退款交易。

pull over push

合约不主动把退款推给被超过的人，而是记账，让用户自己来拉。主动转账时，如果对方是恶意合约，可能重入；如果对方拒收，整个出价交易会失败。记账 + 自取更安全。

3.8

结算（等 5 分钟后）

拍卖到期后，任何账户（A/B/C 都行）都可以打开 Proxy 地址 → Write as Proxy，找到 endAuction，填 auctionId = 0，Write → 确认。

原理

endAuction 先检查 block.timestamp >= endTime，把 active = false，再把托管的 NFT 转给赢家，最后按 proceeds = highestBid - fee 给卖家、fee 给手续费收款人。如果无人出价，NFT 退回卖家。endAuction 任何人可调，卖家不能拖着不结算。

3.9

升级到 V2（UUPS）

新建 ignition/parameters/upgrade.sepolia.json：

{
  "UpgradeMarketToV2Module": {
    "proxyAddress": "0x你的Proxy地址",
    "highValueFeeBps": 100,
    "highValueThreshold": 10000000
  }
}

highValueThreshold = 10000000 表示 10 USDC（6 位小数）。10 USDC 以上的拍卖走 1% 费率；如果演示 ETH，阈值要按 wei 填（例如 0.01 ETH = 10000000000000000）。

npx hardhat ignition deploy ignition/modules/UpgradeToV2.ts --network sepolia --deployment-id upgrade-sepolia --parameters ignition/parameters/upgrade.sepolia.json

截图：升级交易 + version() 返回 v2。

UUPS 升级到底改了什么

Proxy 里有一个固定的 ERC1967 存储槽，存着「当前实现地址」。upgradeToAndCall(newImpl, data) 做两件事：把槽改成 newImpl，然后 delegatecall 调用 newImpl 的 initializeV2。Proxy 的地址、NFT、拍卖、余额数据都不变；只是以后所有调用都走 V2 的代码。initializeV2 用 reinitializer(2)，表示「这是第 2 次初始化」，只能成功一次。只有 owner 能升级（_authorizeUpgrade 有 onlyOwner），所以升级模块必须用 A 的私钥部署。V2 只改了 _calcFee：金额 ≥ 阈值时用 highValueFeeBps，否则用 feeBps。
